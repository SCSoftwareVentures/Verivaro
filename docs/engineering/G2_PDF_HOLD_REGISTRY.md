# Local legal-hold journal and cross-process deletion lock

The offline operator-only registry provides the existing deletion lock and live hold-check interfaces. Tenant/project/quarantine/original-hash combinations are mapped to keyed HMAC file names under a strictly owner-controlled mode-0700 directory. An atomic O_EXCL lock file ensures that hold mutations and deletion transactions cannot overlap across cooperating processes on the same local filesystem. A crash leaves the lock in place: it is never silently expired or removed. Administrative reconciliation is required before manual unlock.

Legal hold status is a mode-0600 append-only ordered HMAC-SHA-256-chained journal. Each entry binds the scoped original hash, actor, reason, time, prior MAC and status. Each read verifies the full chain, file owner/mode and exact JSON representation. No entry means unknown, never clear. An injected trusted authorizeChange function must explicitly approve every hold or release; it has no permissive default. This local registry is for a single filesystem/trust domain, NOT a multi-host authoritative legal-hold system. A production authorization/identity service, independent backup of the journal, key rotation and recovery controls are still required. Tampering with the MAC key and journal together cannot be ruled out. No public APIs or automatic purge are enabled.
