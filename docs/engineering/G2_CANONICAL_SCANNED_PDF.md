# Canonical image-only PDF / OCR integration

The new `scanned-pdf.mjs` accepts and generates a deliberately narrow single-page, noninteractive PDF with one 8-bit RGB /DeviceRGB image XObject and only a fixed draw command. Bounding: 256 KiB original, 2048 px max side, <=1,048,576 pixels, bounded zlib expansion and input consumption. The parser reconstructs all PDF bytes/objects/xref and compares them exactly, rejecting extra objects, actions, scripts, attachments, trailing data, altered dimensions or compressed garbage. Its derived strict PNG is ephemeral and never replaces the encrypted original PDF; original and raster SHA-256 are both bound into derived OCR region digests, persisted source coordinates and independent OCR review. Existing PNG OCR digests and stored source records are unchanged. SQL migration 0061 adds type-coherent, validated PDF page 1 plus derived raster digest to OCR locators, without relaxing generic requirement approval. PDF text extraction fails closed for image-only files and directs users to OCR. The workspace offers both PNG and image-only PDFs with a clear restriction. Includes adversarial unit tests, live encrypted database provenance tests and independent Poppler rendering in CI. This is **not generic PDF OCR**: arbitrary scans, multipage PDFs, mixed text/image content and alternative encodings remain unsupported. No paid services, merge, deployment or production infrastructure changes. CI pending.
