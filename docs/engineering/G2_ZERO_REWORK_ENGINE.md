# ZeroRework dependency evaluator — F07/F25/F26/F27

Pure scoped DAG evaluator and private-state incremental evaluator. Explicit edges connect a dependent exact criterion version to a prerequisite requirement and its previously approved effective SHA-256 fingerprint. Each node has a trusted, canonical local assessment digest and local readiness state. Every result includes its effective fingerprint and deterministic upstream issues. Changes in prerequisite content, revision, evidence, local readiness or upstream dependency state propagate across the full downstream closure. A prerequisite must both be satisfied and match its exact pin; not-applicable is not a valid prerequisite satisfaction. Affected approvals must be reassessed by the authoritative service; this module cannot authorize an updated pin. No original records are mutated.

Bounded graph: 128 requirements, 1024 edges, eight prerequisites per requirement. Reject duplicate nodes/versions/edges, unknown endpoints, cross-scope records, wrong dependent versions, cycles and self-links. Deterministic ordering; removed edges/nodes use old and new reverse adjacency. Incremental dirty roots are derived from complete normalized graph input, not user-supplied change hints. Recompute only roots and downstream closure; compare against full recomputation in tests. Internal cached findings are immutable and inaccessible for mutation by callers; invalid update retains previous state. Input validation and topological ordering still run for the entire graph.

This is an isolated engine, not yet used for release authorization or PostgreSQL readiness evaluation. All node digests and pins must come from authenticated authoritative graph records; arbitrary caller values are not trusted. Persistence, separate reviewer authorization of edge/pin changes, transaction-bound database assessment, release-gate integration, UI and recovery coverage are outstanding. Current database assessment continues its existing exact revision/full recomputation rules. No claim of production-scale speed or gate acceptance. Eight automated cases, including 80 incremental-vs-full comparison iterations.
