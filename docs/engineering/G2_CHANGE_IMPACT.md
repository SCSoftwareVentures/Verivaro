# G2 ChangeImpact: historical submission graph comparison (F26/F27)

Authenticated, same-origin POST `/api/v1/tenants/{tenantId}/projects/{projectId}/verification/submission-impact` accepts exactly `{"submissionId":"<UUIDv4>"}`. It uses existing scoped immutable snapshot inspection and then the current scoped assessment. It checks the stored manifest SHA-256 and both project scopes. No direct DB access or new permissions. The historical snapshot is immutable; the current assessment is a point-in-time read. No new approvals, writes or evidence retrieval occur.

Reports added/missing requirements, version or criterion changes, source changes, rule review changes, evidence link changes, evidence review/integrity changes, readiness changes and associated evidence identifiers. Unrelated requirements remain unchanged; UI permission hints, evaluation timestamps and link ordering do not create false changes. Returns current readiness status and blocker count plus archived state. Does not assert that a package remains authorized: project metadata, authorizer identity, expiry and session checks remain in the existing release gate. No automatic legal inference or approval carry-forward.

This is direct, persisted-data comparison, not a transitive requirement dependency implementation. Explicit dependency edges, dependency approval/versioning, selective recomputation, scheduling links, browser presentation and live HTTP acceptance tests remain open. Unit tests and live database integration cover unchanged baseline, new links, and revised criteria. No production claim.
