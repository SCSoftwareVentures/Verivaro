# Verification report exports

Authorized owner/reviewer routes GET .../report-pdf and .../report-package derive each export from one database snapshot (the same scope checks as report JSON). PDF attachment contains project identity, revision, lifecycle, UTC timestamps, evidence and review summaries, full evidence SHA-256 register and review history. A fixed server-side PDF writer emits only escaped text, fixed drawing commands and built-in fonts, with no active content/attachments/remote resources. Non-ASCII characters are represented by codepoints in the PDF; JSON retains original Unicode. No secret, storage reference or evidence contents included. ZIP uses STORE only and fixed entries verification.json, verification.pdf and manifest.json; both reports come from the same snapshot, manifest records byte lengths and SHA-256. HTTP X-Report-SHA256 hashes actual response bytes. Checksums are not signatures. PDF explicitly states unsigned database snapshot and includes hash of exact JSON. Independent custody checkpoint remains separate. No claim of PDF/A compliance, legal admissibility or independently certified factual accuracy. Limits: original 4096 evidence/2048 requests and 2 MiB JSON, maximum 1000 PDF pages / 8 MiB PDF; fail closed if limits exceeded. Packages include metadata only, not raw evidence. Same-origin authentication, current roles, rate limits, no ranges, no caching, fixed attachment names; no tenant or project identifiers accepted from report body. The browser displays metric cards and three export choices. No deployment or fees.
