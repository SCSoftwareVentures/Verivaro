# G1 protected download gateway

Candidate HTTP adapter uses POST /public/share/download and Authorization: Bearer <token>; no token in path/query, no request body, no ranges. Client-facing share landing page/token exchange still required. Dedicated private PostgreSQL role resolves tokens before and after retrieval. Full artifact SHA-256 is verified before any bytes are emitted. Only attachment responses, no-store, restrictive headers, opaque fixed filename and generic denial. No public object URL or internal handle is returned.

The initial private local filesystem adapter uses a trusted isolated absolute directory, UUID-only filenames, no symlink following on the file, regular-file checks and a bounded read. Ancestor directories must be exclusively controlled by the deployment owner. This is not a cloud object storage integration. Max 8 MiB by default (hard cap 32 MiB per request), maximum four concurrent downloads by default. Concurrency slots are held until response flush or disconnect, and the response is destroyed on timeout if still transmitting. Larger exports require disk spooling or authenticated chunk manifests; process-local rate limiting must be replaced/supplemented by shared perimeter limits for multiple replicas. Proxy must not log Authorization, enforce TLS, request/header/connection timeouts and avoid trusting supplied forwarding headers. The request deadline is cooperative: storage must honor abort, and database pool acquisition/statement timeouts must be configured by deployment. No proof of client receipt; database records each authorization check, not actual delivery. Already released bytes cannot be recalled, and revocation can occur between the final check and transmission. Recipient-bound sensitive sharing, production storage and public UI remain outstanding. No deployment or real data used.
