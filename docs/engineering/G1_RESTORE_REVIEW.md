# Restore readiness review (not activation)

Use readRecoveryInventory on the frozen source and restored database. A complete matching verified evidence receipt (backup UUID, exact separately trusted catalogue digest and normalized inventory digest) must be recorded by the trusted recovery administrator after actual validation. Restore-only quarantine adds immutable receipt and reviewer records, and two distinct current non-superuser DB login principals with verivaro_restore_reviewer membership are required for review_ready. Unique case references attest to review of current identity/entitlement reconciliation, key rotation, evidence and object mapping, external alert/receiver reconciliation, resource cleanup and environment isolation. Each login must represent one independently verified human. Role membership revocation invalidates readiness while revoked; regrant of the same login can restore an earlier review, so deprovision permanently and allocate fresh login identities. DB cannot verify actual human actions or physical storage, and a trusted administrator can misrepresent a receipt. Review readiness alone never grants CONNECT, unlocks identities, or promotes a database. Operator review access must be provisioned solely on an isolated cluster; ordinary application access remains prohibited. No production approval or cutover performed.

Live CI deliberately rejects the prior adversarial fixture database's missing placeholder evidence; a separate SQL-backed synthetic inventory verifies actual object roundtrip and review permissions with a simulated receipt in a rolled-back transaction. This does not establish a complete production restore. A real full-object consistent snapshot with provider integration, role provisioning, and independent reconciliation remains required.
