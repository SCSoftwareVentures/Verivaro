# ProofLock authenticated capture upload

POST /api/v1/tenants/{tenant}/projects/{project}/evidence/capture/{window}/{criterionVersion}/{milestoneRevision} uses the existing authenticated raw-body upload, bounded supported formats, hash check, malware scanner, sealed storage and quota. The database prechecks the exact approved capture rule and scope; the final transaction rechecks current scope, criterion and schedule, commits evidence, links it for independent review, and writes an immutable receipt containing server received time and the original deadline. Conflicts roll back the entire transaction. Exact retry returns its original result under current permissions, while stale fresh capture is denied. Server receipt is not proof of original capture time or site status. This neither verifies evidence nor authorizes release.

The mobile workspace includes an original-file picker and an explicitly confirmed device-generated RGB PNG photo derivative. Browser-supported camera input (including JPEG and HEIC only where the browser decoder supports them) is decoded locally, bounded by input size and dimensions, stripped of metadata and scaled as necessary. The user is told the resulting dimensions before upload; originals are not uploaded in derivative mode. The authenticated capture link is a fragment containing only exact scope identifiers, not a credential; stale or unauthorized links do not open an editor. Reopen the link after signing in if the identity redirect loses its fragment. No QR generator, offline queue, original camera timestamp validation, derivative preview or actual iPhone hardware validation yet. No external messages or deployment. HTTPS regression, recovery reconciliation and dedicated Chromium/WebKit browser acceptance tests are added; verify results in CI.
