# ProofLock authenticated capture upload

POST /api/v1/tenants/{tenant}/projects/{project}/evidence/capture/{window}/{criterionVersion}/{milestoneRevision} uses the existing authenticated raw-body upload, bounded supported formats, hash check, malware scanner, sealed storage and quota. The database prechecks the exact approved capture rule and scope; the final transaction rechecks current scope, criterion and schedule, commits evidence, links it for independent review, and writes an immutable receipt containing server received time and the original deadline. Conflicts roll back the entire transaction. Exact retry returns its original result under current permissions, while stale fresh capture is denied. Server receipt is not proof of original capture time or site status. This neither verifies evidence nor authorizes release.

The mobile workspace includes a contextual file picker for supported PNG, UTF-8 text and canonical text PDF; no arbitrary JPEG/HEIC, device-camera conversion, QR or external/anonymous capture link, offline queue, or capture timestamp validation yet. No external messages or deployment. HTTPS regression and recovery reconciliation added; dedicated UI capture interactions remain to be tested.
