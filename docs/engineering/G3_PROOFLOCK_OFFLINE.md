# Encrypted offline capture increment

An already loaded authenticated capture editor can explicitly save a supported original or approved camera PNG derivative to a bounded IndexedDB queue (eight entries, each at most 256 KiB). AES-256-GCM authenticates ciphertext against a random request identifier; a distinct 128-bit salt and 96-bit IV are generated for each entry, deriving a nonextractable key with PBKDF2-SHA256/600000 iterations from a user-supplied 16–128 character passphrase. The passphrase and key are not persisted. Actor, scope, exact schedule revision, media type, digest and bytes are encrypted; opaque IDs remain visible. Storage loss, malicious same-origin scripts, device compromise and weak passphrases remain risks; no promise of secure deletion or recovery. No account/session token is stored. Use only on a trusted personal device.

Manual synchronisation requires correct passphrase and same actor/context, verified again against the signed-in token by the upload handler. The exact request ID survives interruption and reload. Receipt match is checked before local deletion. Errors, stale schedules and rejected bytes retain the local entry; no automatic retargeting. Local entry management provides explicit discard. Existing server quotas, scanning and independent review remain mandatory. A page must already be loaded to capture without connectivity; there is no service-worker application cache, background sync, export or full offline startup. No external notifications. Browser tests exercise encrypted persistence, incorrect passphrase, interrupted upload and replay; live HTTPS checks actor binding. Actual iPhone storage/decoder validation remains outstanding.
