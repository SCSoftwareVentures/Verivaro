# Encrypted batch recovery and expanded plain-text intake

Explicit local saved batch: AES-GCM with 96-bit random nonce, PBKDF2 SHA-256 600000 iterations and random salt, distinct IndexedDB database, two batches maximum. Actor, tenant, project, batch identity, original request IDs, filenames and original bytes are authenticated inside the encrypted record. Resume verifies scope and per-file digests. Replay uses identical request IDs; exact upload and lineage idempotency handle a lost response. Upload header binds intended actor to current authenticated actor. No automatic background sync. Save before first upload; manual discard after completion. Storage eviction or lost passphrase cannot be recovered. No cross-device recovery. Supported file count and size limits unchanged (12 x 256 KiB). CSV and Markdown are accepted as raw UTF-8 text through the existing strict validation and scanner, not rendered or interpreted as active documents; filename lineage preserves original extensions. ContractIQ deterministic obligation-line-v2 adds obligation, prohibition and timing cues while preserving exact source quote hashes and original modal-line-v1 provenance. Separate source import function records new algorithm version. No generalized OCR, DOCX/XLSX, arbitrary PDF, semantic model or legal interpretation. Unit/browser tests added, full CI pending.
