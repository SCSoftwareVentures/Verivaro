# Hardened application runtime

Run from the engineering checkout using Node 22.16.0:
- npm ci --prefix services/application/driver --ignore-scripts --no-audit --no-fund
- node services/application/main.mjs /absolute/private/config.json

Never commit the configuration or credentials. All referenced files must be absolute, regular, owner-only, owned by the process user, non-symlink files with trusted directory ancestors. The JSON has exact fields: origin (fixed https origin), listenHost (127.0.0.1, ::1 or explicitly 0.0.0.0), listenPort (1024–65535), tlsKeyFile, tlsCertFile, database {host,port,name,caFile}, logins {identity,runtime,admission} each {user,passwordFile}, provider {issuer,audience,authorizationEndpoint,tokenEndpoint,requiredAcr,requiredAmr,authorityFile,checkpointFile,catalogueFile,signatureFile,clientSecretFile}, local {issuer,audience,signingKeyFile}, secrets {browserKeyFile,contextKeyFile,admissionKeyFile}. Keys in secrets files are distinct canonical 32-byte base64url values. Provider catalogue/checkpoint must be separately approved and protected, signature raw 64 bytes and authority public PEM. Local signing key RSA >=2048. Passwords distinct; dedicated roles validated at connection and real database TLS required. Application listener verifies matching SAN and certificate/private key, permits TLS 1.2+, emits HSTS, no proxy headers trusted. Use a dedicated unprivileged OS user, restricted network and egress, production TLS CA, secrets provisioning and supervisor. No plaintext listener. Startup fails closed on missing/unsafe files, duplicate credentials/keys, privilege drift, bad certificate or unsigned/expired keyset. Does not automatically rotate files; restart under change control.

Integrated browser and three read-only application API routes; root serves a minimal sign-in/out page, not a complete product UI. Central strict Host/framing boundary, no body routes, sensitive header duplication rejection, auth peer quotas, API peer/actor quotas, process cap 24 in-flight, 128 sockets, 16 per normalized peer, handshake/header/request/idle timeouts, no upgrades or CONNECT, graceful drain. Limits are defensive defaults, not load-test guarantees; direct TLS topology only, proxy/NAT needs separately designed edge controls. No raw request log or credential output; supervisor must protect stderr and access logs. CI uses real HTTPS and PostgreSQL TLS with synthetic provider responses; validates browser session through actual scoped API and global logout. No external provider, production deployment, browser engine or production network validated. Write endpoints and idempotency are deliberately deferred until the mutation authorization design is ready.
