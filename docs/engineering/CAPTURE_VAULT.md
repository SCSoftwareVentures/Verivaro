# Encrypted offline capture vault

Uses PBKDF2-SHA256 600,000 iterations, random salt, AES-256-GCM, fresh 96-bit nonce per write, non-extractable key held only in memory, AAD binds exact server-verified tenant/project/actor fingerprint and record version. Metadata and file bytes encrypted together; per-file hashes checked before saving and after decryption; no stored login token/passphrase. Atomic compare-and-swap rejects concurrent-tab writes. Reconnect to authorised project, enter passphrase and explicitly retry. Persist before issuing writes; replay exact immutable document and intent IDs from initial stage after reload; remove after quarantine acknowledgement. Incorrect passphrase/corruption fail closed; explicit destructive reset available. No automatic networking or offline authentication. Disconnect clears unlocked session references, not encrypted storage. 
Limits: authenticated page must already be open to capture offline, and reload restoration requires server reconnection plus passphrase. Not a service-worker/PWA or background sync solution. Browser may evict data, no guaranteed secure erasure/backup, local compromised browser or malicious extension can access unlocked data; offline revocation cannot remotely destroy copies. Scope hash, ciphertext size and timing may leak metadata. Passphrase strength depends on user; forgotten passphrase cannot recover.
