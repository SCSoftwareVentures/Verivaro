# G1 scoped API and quarantine orchestration — draft

CI #8/#9 both passed at 06e5ea796ead04fc178ed891978cbd61442b3a98. The next slice provides a Node HTTP server factory and service functions for project metadata, document creation, intent creation, status and upload bytes. Identity verification, parameterised SQL, signer calls and runtime transaction context are connected through injected node-postgres-compatible pool contracts. A distinct trusted worker pool records quarantine receipts. No client can submit signer claims or scan results through these routes. Membership and original intent owner are checked before storing bytes and again before committing receipt metadata. No database transaction remains open during streaming. All responses omit private storage keys. The original upload UUID and immutable metadata support replay responses. There is no download or release-to-evidence pathway.

## Verification boundary
Real PostgreSQL SQL tests exercise permissions, RLS, signer and status procedures. Node tests use synthetic signed JWTs, mock pool implementations, actual temporary filesystem and actual loopback HTTP traffic. This is not a live database-to-HTTP integration test. Local registry access was unavailable during development; the repository intentionally does not vendor or introduce an unlocked database driver. Inject separately authenticated pools with bounded connection acquisition and timeouts. A driver, pinned lockfile, real multi-login connection integration, actual adapter wiring, OpenAPI contract, deployable process separation and runnable install are still required before G1 acceptance. Native HTTP is a temporary dependency-free transport choice, not a final switch away from the proposed Fastify architecture.

## Residual risks and constraints
Do not treat synthetic JWTs as live authentication: dedicated API token issuance, provider token type, key rotation and revocation integration remain outstanding. Distinct pool objects do not prove distinct DB credentials; tests with real separate login identities required. The worker receipt call is a separate transaction: an uncertain outcome, policy denial during upload or concurrent duplicate can leave private orphan files. No automatic deletion on ambiguous results; safe reconciler, reservation/lease, durable job dispatch and storage quota remain next priority. The signer and worker are high-trust interfaces; production credentials must be separated into independently controlled services. Service presently holds membership locks for receipt registration; test concurrent revocation. HTTP has bounded JSON and stream size and inactivity/request timeouts; global concurrency, rate limiting, request body rejection handling under load, proxy TLS, CSRF if cookies introduced, and audit for failed requests remain open. No real malware scanner, parser, production credentials or deployment. No release approval.
