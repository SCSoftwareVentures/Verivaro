# TrustProof v1 decision integrity ledger

32 explicitly selected immutable graph, submission, ProofLock, financial, chronology, coordination and CustomerAccess record types produce a source-row SHA-256 digest and a per-project append entry in the same database transaction. Source row serialization uses UTC PostgreSQL JSONB text. Hashes bind tenant, project, sequence, type, source UUID, origin, chain recording timestamp, source digest and previous hash. Backfill locks source tables and is explicitly marked as structural migration order, not historical chronology. No plaintext source row is exposed in audit exports.

Owner/owner and reviewer/reviewer may request bounded pages; the database reconciles source counts and recomputes each selected row digest. Node checks continuity and hash validity; browser checks page continuity and head consistency and exports JSON. The offline verifier accepts a retained independent head/cursor and fails on changed digests, sequence, scope, counts or source-integrity assertion. A full scan is necessary for whole-chain assurance. Source integrity flags/counts are DB attestations, not independent raw-source verification. No trusted timestamp, independent signature, privileged-administrator tamper immunity, or claim of delivery. Preserve the head externally; a privileged writer who rewrites the whole ledger and all anchors can otherwise evade hash-only detection. This is selected decision coverage, not the entire security/access/audit lifecycle. Custody, retention/deletion policy, signed checkpoints and browser acceptance remain outstanding.
