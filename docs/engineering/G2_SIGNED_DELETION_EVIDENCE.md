# Signed original-PDF deletion evidence (review branch only)

Deletion cannot proceed unless an independent Ed25519-signing ledger has **durably written and read back** an authenticated `prepared` record into a separate root directory. This record binds the precise tenant/project/quarantine/source SHA-256, signed-approval payload digest, deletion UUID, signing public-key fingerprint and creation time. The original encrypted file remains present through the entire preparation step. After unlink, the ledger independently checks absence at the nominated path and durably signs a linked `completed` record. The local tombstone is promoted only after the completed receipt is verified. Failed or interrupted completion leaves the original local deletion intent in place, denying reads and retry; it must be reconciled manually, not automatically classified as a successful deletion. A corrupt or truncated signed archive fails closed, as do key substitution and scope changes. Signatures can be independently verified with an **externally trusted** Ed25519 public key.

**Critical scope:** The archive uses a separate local directory but is not automatically an offsite backup or independent storage system. The signature records what the controlled operator process asserts at signing; it does not establish physical secure erasure, absence from snapshots/backups, true legal authorisation or a trusted external timestamp. Production still requires independent archive replication, audited key custody, durable reconciliation and disaster recovery. Neither the public upload route nor any scheduler invokes deletion. No live customer data, merge or deployment.
