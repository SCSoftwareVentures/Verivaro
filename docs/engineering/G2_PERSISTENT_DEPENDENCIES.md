# Persistent requirement dependencies (0038)

PostgreSQL stores immutable dependency proposals and independent review decisions. Same-project current versions only; maximum eight prerequisites per version, globally bounded rows. Pins are computed inside the database from the prerequisite's effective assessment including transitive dependencies, source and evidence integrity, excluding actor-specific UI hints. A proposal is allowed before the dependent criterion is reviewed and only for a satisfied prerequisite. Separate reviewer cannot be the proposer or criterion author. Pending, rejected, stale or unsatisfied prerequisites block readiness even for optional dependent criteria. Existing submissions re-run the full authoritative assessment before authorization and download. Historical manifests are unchanged; projects with no dependencies keep existing shape. Revision approval cannot omit previously declared prerequisites.

Implementation intentionally permits only additive dependency declarations (revisions must redeclare earlier prerequisites); reviewed removal or exemption is not implemented. Evaluator is full deterministic database traversal, not cached incremental execution. HTTP/browser controls are not yet exposed; scoped runtime database adapter provides operations. SQL pin serialization is PostgreSQL JSONB-specific; it is not the same encoding as the standalone JavaScript prototype. Migration, privilege allowlist, integration and restore content reconciliation are included in hosted CI. No production or independent audit claim.
