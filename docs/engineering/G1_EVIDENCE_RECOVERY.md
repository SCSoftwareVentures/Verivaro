# Evidence recovery and trusted catalogue

Evidence and released export objects are backed up by stable UUID filenames from a trusted private storage directory. Never follow storage_ref URLs or paths. The inventory must be the complete set of evidence.id/sha256 and released_exports.artifact_id/sha256 from the same quiesced database snapshot; duplicate IDs with different hashes fail. Each object is encrypted using the authenticated archive format and checked against its database hash. A signed Ed25519 catalogue binds object IDs, per-object backup IDs, hashes and sizes to the database backup ID/hash/time and installation. Entire encrypted bundle is published only after all objects succeed. Maximum 4096 unique objects, 512 MiB per object, 2 GiB total. The restore verifies a separately trusted exact catalogue digest and sequence, signature, database backup identity, default 24-hour database freshness window and complete expected inventory; no partially verified directory is published. Restore writes actual files into a new private directory (not a serving store); production destination requires encryption at rest and trusted ancestors. The external checkpoint must be stored independently with rollback-resistant governance. The prior digest is recorded for catalogue chaining; current code requires the exact externally supplied checkpoint and does not implement a distributed catalogue or independently validate all predecessors. Signing key must be independent of the backup encryption key. No automatic activation. Quiescence or immutable versioned storage plus consistent snapshot orchestration is required; the library does not stop writers. Missing legacy storage mappings fail closed. A production provider adapter, external key custody, off-site immutability, retention and larger-volume support remain outstanding.
