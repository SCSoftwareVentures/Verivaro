# Alert delivery and controlled incident resolution

Migration 0014 creates a transactional outbox for newly committed incident-opened/escalated events. No historical alerts are enqueued. Separate sender credentials claim one row with SKIP LOCKED, a random fencing token and 60-second lease. Five total attempts, retry delays 30/60/120/240 seconds; abandoned final claims become dead-letter on next claim poll. Accepted means HTTP 2xx response only, not human receipt. At-least-once attempts: remote receiver must persist the stable installation-ID/event-ID idempotency key and verify the HMAC signature, timestamp and replay policy. There is no exactly-once external side-effect guarantee. Retried ambiguous delivery may duplicate a notification if receiver ignores the key. Dead letters require operator review; no automated replay. The dashboard displays aggregate delivery status. Queue and audit retention/pruning and dead-letter replay workflow remain future work.

Use the existing pinned monitor driver, a separate least-privilege sender login, and explicit VV_ALERTS_ENABLED=1 to run node services/security-monitor/main.mjs alerts. Set deployment-approved fixed HTTPS VV_ALERT_ENDPOINT (no user-provided URL), UUID VV_INSTALLATION_ID and canonical 32-byte base64url VV_ALERT_HMAC_KEY via protected configuration. Enforce outbound network allowlist, DNS policy and certificate validation at deployment; URL syntax checks alone are not SSRF protection against misconfiguration. No redirects, five-second fetch timeout, minimized event payload, no raw response logging. Only a single approved receiver per installation is supported. Integration uses injected synthetic transport; no real external notification sent, no external account connected. Endpoint availability, receiver deduplication, secret rotation, production delivery and independent supervision remain unverified.

Operator acknowledgment still mandatory before closure. New resolve_incident(id, resolution_ref, reason) requires a unique documented evidence/case reference and controlled reason; old unreferenced operator close is revoked. Evidence is a human-attested correlation reference, not verified remediation. No autonomous account lockdown, lease reclamation, or external action. Operator credentials remain separate. All actions stay within approved project scope.
