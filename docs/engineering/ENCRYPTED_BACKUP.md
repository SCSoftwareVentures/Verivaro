# Authenticated encrypted backup increment
Operator-owned AES-256-GCM backup envelope, bound to key identifier and object/database context, random 96-bit nonce, authenticated header, explicit plaintext size, 1 MiB streaming chunks, 16 GiB default / 32 GiB maximum per file. Source and destination must be private owner-controlled directories; only regular non-symlink input, no overwriting; stage privately, validate final authentication before publishing output and fsync. Invalid tags, wrong key/context, truncated files, oversize, input changes and overwrite attempts fail closed. Private staging may leave plaintext disk remnants on interrupted decrypt; disk encryption and controlled temp storage remain necessary. Key management, rotation and independent durable backup location are buyer-controlled. Not a guarantee of secure deletion or backup availability.
The existing disposable PostgreSQL recovery drill streams pg_dump rather than collecting it in a 16 MB memory buffer, encrypts the DB archive and every original, restores only authenticated bytes and re-verifies original SHA256. Restored database is still isolated; empty erasure ledger inventory is a synthetic fixture only. Production requires complete externally trusted ledger inventory before cutover; a missing erasure tombstone blocks opening. Large-scale 16 GiB performance, remote storage and KMS integration not tested; default and maximum are code limits, not verified capacity. No migration or real-data backup executed outside CI.
