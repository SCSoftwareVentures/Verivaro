# Controlled dependency removal (0039)

A removed prerequisite is never deleted. A new criterion revision may propose a removal only for a historical prerequisite of the same scoped requirement, with a reason. The database resolves the historical edge, checks current membership and exact revision, and requires a different reviewer from the proposal and criterion author. Rejected or pending proposals cannot satisfy continuity; an approved removal applies to that exact revision only. Active dependency pins and removal proposals for the same prerequisite cannot coexist. Every subsequent revision must redeclare or independently renew the removal. Revision approval and current readiness remain fail-closed. A removal is not proof that the underlying obligation is legally unnecessary.

Manifest and upstream fingerprints include immutable removal proposal and decision details. Historical snapshots remain intact; dependent approvals need reassessment after a removal. Candidate discovery is scoped, separate from the canonical manifest, and provides only current eligible historical prerequisites. Authenticated workspace controls allow proposal/review; authoritative database roles enforce independence. Backup reconciliation and privilege audit cover both new tables. Integration tests cover pending/rejected decisions, self-review, conflicting active pin, exact retry, stale downstream package, renewed readiness and renewed exemption requirement. Browser and HTTP regression for the new removal controls are not yet specifically exercised. No legal conclusions or production claims.
