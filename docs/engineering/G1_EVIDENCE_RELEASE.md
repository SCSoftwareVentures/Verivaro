# Controlled evidence review and release

Migration 0025 replaces direct export registration for the release service with an exact evidence approval workflow. It revokes pre-workflow exports rather than inventing historical approvals. Existing audit records are preserved; the trusted migration/database owner remains a privileged boundary. Initial policy is three distinct actors: original evidence uploader (current contributor/reviewer/owner in both tenant and project), independent reviewer (reviewer in both), and separate releasing owner (owner in both). A single reviewer records one final approved/verified or rejected/reason decision; reviewers cannot approve their own submission. Each request binds immutable evidence ID and SHA-256. Request and review are idempotent for exact retries with the same current entitlement generation. Concurrent review writes serialize. Submission expires after seven days; approval expires for new release after 24 hours. Membership and identity generation changes permanently invalidate earlier approvals for publication. The approval is a human attestation, not a guarantee of semantic accuracy, and does not assert a signed external timestamp.

The fixed workflow adapter uses a pinned runtime database login; publication uses a separate pinned verivaro_release_service login. The release function accepts only the exact requested evidence ID/hash and creates the existing release/export record and immutable receipt atomically. New exports are recipient-only; no bearer links. A single artifact can be released once (unique artifact ID); revoked exports cannot be reactivated by retry. Requests/reviews/receipts immutable, caps 8 requests per evidence and 16384 globally. Existing authorized recipient resolution separately rechecks current sharing owner and recipient credentials. Revocation denies future downloads; prior completed deliveries cannot be recalled. Reviewer/submitter changes invalidate pending release, not already-published exports; revoke published exports explicitly. Restore revokes all exports and disables actors, and preserves the three workflow record tables. No automatic reactivation.

createEvidencePublisher materializes verified original bytes by exclusive temp file and atomic no-overwrite link in an owner-only private directory on an encrypted volume, fsyncs file and directory, and then commits the approved registration. It verifies the existing file on retry, rejects symlink/unsafe mode/content mismatch, and never exposes an unregistered file through the share gateway. Failed DB commit can leave an unregistered orphan; operator must reconcile files against release inventory, never automatically delete. The release directory is a separate trusted immutable storage boundary: only the supervised publisher writes it, gateway reads it. Files are plaintext at filesystem layer, so encrypted volume and private ancestors are mandatory. Existing evidence backup deduplicates original and export artifact IDs (same bytes/hash). This module is a service-level workflow; browser review screens, runtime HTTP request/review/publish routes, permission-management UI, independent production storage and provider integration remain outstanding. CI uses real pools, real private files and recipient HTTP with synthetic user tokens and scanner verdict, not production deployment.
