# ProofLock batch: alerts, receipt reconciliation and recovery guidance

The scoped prooflock read now includes immutable capture receipts and the current project alert policy in one stable PostgreSQL statement. A deterministic in-app alert view deduplicates by exact project/criterion/window/schedule revision, urgency bucket and phase. Routine items form a digest; critical/high items are prioritised. Owner-controlled versioned project settings define local timezone, quiet hours and optional critical override. Quiet hours change only in-app priority presentation; there are no scheduled jobs, push, mail, or external delivery.

Receipt reconciliation differentiates receipt before/after deadline, pending independent review, and unknown deadline. Elapsed superseded windows remain visible. Retrospective approvals are not classified as proven missed obligations. An approved timely receipt does not prove original physical capture time. Recovery guidance directs the user to evidence permitted by the confirmed criterion and independent review; never automatically substitutes late photos or authorises waivers. A formal exception/alternative evidence approval workflow remains outstanding. Project-level settings are intentionally narrower than tenant-wide default policy; no external configuration is touched. Unit and live HTTPS tests, restoration checks and role-grant audit updated. Dedicated browser acceptance for the new controls remains outstanding. Full verification is deferred to the grouped engineering checkpoint.
