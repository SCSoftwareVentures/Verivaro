# Isolated PDF worker: authenticated local conversion boundary

The new PDF worker is a separate application principal and has **no HTTP interface**. A Unix domain socket in a non-world-readable directory has independent 32-byte secret credentials, fresh 256-bit client and server nonces, an HMAC worker proof verified before original PDF bytes are sent, and domain-separated HMAC-SHA-256 authenticated frames for requests and responses. The client independently parses the canonical PDF and checks all source, derivative and per-page raster digests; forged, truncated, oversized, unauthenticated and changed-result frames fail closed. Source bytes are allowed only as bounded original-PDF input and are not accepted by the existing evidence upload route. The converter executes Poppler only on the worker side.

A *proposed* Linux systemd service creates the dedicated `verivaro-pdf` identity, AF_UNIX-only socket access, network isolation, read-only filesystem, restricted capabilities, no core dumps, private /tmp, memory/CPU/task/FD quotas, no kernel/namespace changes, and credential delivery. It is **not installed or enabled**. Actual CI tests exercise private socket authentication, forged-worker rejection and Poppler rendering with independently verified output. They do not prove systemd/cgroup/seccomp enforcement on production infrastructure.

The worker is for manual/offline operator-controlled pre-admission conversion only. Do not route raw PDFs into the browser application or describe a derived image-PDF as original evidence; retaining and cryptographically linking the original requires a separate quarantine/custody system with its own malware, privacy and storage controls. No keys, user documents or production infrastructure created. No merge/deployment or paid resources. CI pending.
