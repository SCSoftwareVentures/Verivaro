# Read-only recovery and reconciliation of original-PDF deletion evidence

Adds a strict offline auditor for signed deletion stage/completion, the independently verified replica, the encrypted original filename, and local write-ahead intent / tombstone. A verified outcome is classified only if the original has disappeared, the primary and mirrored Ed25519 receipts match, and the local receipt scope/approval digest matches the signed prepared event. The tool distinguishes retained originals, prepared-but-not-deleted, interrupted-before-unlink, missing-original-without-completion, completed-but-local-tombstone-pending, and fully verified local completion. Ambiguous, mutated, symlinked, missing, inconsistent or unsigned records cause an error rather than silently assuming success. It never deletes, retries, restores, removes a stale lock or clears a legal hold. Recovery tests simulate all stages using synthetic temporary files, including deliberate tampering and contradictory states.

A result of `signed_completion_verified` means the *local* original path is absent and both signed records align; it is not a physical-erasure guarantee or proof that remote backups were purged. Both copies are on ordinary CI filesystems; off-host storage and independent verified recovery remain deployment obligations. Automated reconciliation is deliberately withheld because legal-hold state, backup retention and original-file integrity must be manually assessed before any mutation.
