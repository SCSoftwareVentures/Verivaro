# G1 quarantine and ingestion audit — draft

CI #4/#5 failed because the restricted owner could not create a schema. Migration operator now creates vv_api with the intended owner; no database CREATE grant is added. CI #6 passed the correction.

New local Linux quarantine adapter writes non-overwriting random keys to a private worker-owned directory; streams and bounds bytes; compares size, SHA-256 and coarse media signatures; rejects invalid UTF-8 and NUL in text. File permissions 0600, directory private, symlink checks. Scanner interface re-reads and hashes the file, checks bounded size, returns unavailable on missing, failed, invalid or timed-out scanner responses. Clean is a reported scan result, not proof of safety or permission to release. Synthetic scanner only in tests. A real isolated scanner, engine updates, sandboxing and process-level time/memory enforcement must be deployed and independently verified. Timeout signal is cooperative; cannot stop arbitrary synchronous code.

Database receipts must match scoped upload intent metadata; scans must reference an existing receipt's object key and digest. Dedicated trusted worker role has no raw table, key, or user signing privileges; it may report receipts/scans across queued tenants and is therefore a high-trust boundary. Worker dispatch, lease binding and separate credentials are not wired. Runtime cannot claim a clean scan, read raw quarantine metadata, or create document versions. Atomic insert-trigger audit records member and worker metadata events without document content. Idempotent replays do not add events. The audit is append-only to runtime and worker, not tamper-evident against the database owner; archival, retention, checkpoints and independent verification remain necessary.

Local file adapter and database procedures are separate tested layers: not yet an integrated file service. No HTTP upload URL, S3 bucket, production malware provider, parser, worker dispatch or release path. File cleanup on failures is best effort; orphan reconciliation and durable object-store writes/expiry require separate implementation. Operator controls root and all ancestors, and private directory is not accessible to other untrusted processes. File MIME signatures do not validate file format. No production data or deployment authorised. G1 remains open pending end-to-end tests, full audit and identity/worker integration.
