# Browser evidence approval workspace

Migration 0026 adds scoped workspace discovery (only the authenticated actor's current tenant memberships), project evidence/review lists, and a separate preflight publication check. The preflight validates the exact approval and current permissions before plaintext export materialization; the final registration revalidates them. No user-supplied actor, role, raw storage path or SQL accepted. List results are capped at 200; action hints are not authorizations and do not guarantee approval generations are still current.

The root page serves repository-owned CSS and JavaScript, no inline script, third-party CDN or HTML interpolation. It supports current tenant/project selection, rename, evidence upload/download, submission, review and release. Fixed API routes use same-origin session cookies, exact Origin for mutations, strict bounded JSON, peer/actor limits and role authorization. Browser holds retry IDs for pending attempts in memory; reload loses them, so verify status before issuing a new request. Release review remains terminal. Published reference is displayed; recipient issuance/delivery UI and broader project CRUD, pagination and permission management remain outstanding.

Optional runtime configuration adds release {root} and logins.release {user,passwordFile}; requires ingestion configuration, dedicated validated TLS release pool and existing owner-only private directory on an encrypted volume. Without release config the workspace remains read-only for release operations. Existing uploader/reviewer/owner separation is enforced by SQL, not by UI. Failed registration after successful preflight may leave inaccessible orphan files; reconcile manually. Actual browser-engine/device testing and provider deployment are not claimed by HTTP integration.
