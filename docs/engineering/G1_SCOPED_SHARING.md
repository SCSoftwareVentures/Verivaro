# G1 scoped external sharing authorization

Draft pending CI. The private release worker registers an exact immutable artifact ID and digest for a released export. Bearer access is denied by default; an explicitly non-sensitive approved export may be shared for at most 24 hours. Issuance and revocation require authenticated tenant and project owner status. Delegated manager and sensitive authenticated sharing remain outstanding. The isolated gateway alone resolves a SHA-256 digest derived from a canonical random 256-bit token; the runtime cannot resolve tokens and the gateway has no project/schema access. No token is stored in plaintext. Access returns only the internal artifact ID and digest for an approved grant. Every resolution checks current grant expiry, revocation, export revocation and issuer eligibility.

Gateway must never return storage identifiers to public callers, never log bearer credentials or their digests, accept only raw token through a protected endpoint, compute digest internally, apply rate limits, generic denial, no-store, and no-referrer; do not expose a digest-based endpoint. Use a private streaming delivery service with per-request reauthorization; direct long-lived URLs are forbidden. Audit records successful resolution, not proof of delivery or recipient acknowledgement. Already delivered bytes cannot be recalled. Revocation of project authority denies access while revoked; if reinstatement must not revive links, the incident workflow must revoke the export or affected grants. Account and project administration remain separate release gates. Export worker approval, package integrity verification, HTTP/share UI, recipient binding, actual object storage delivery, concurrency/load tests and retention controls are not implemented by this migration. No live data or external send.
