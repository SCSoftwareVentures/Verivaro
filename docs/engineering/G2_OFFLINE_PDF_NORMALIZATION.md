# Offline external PDF normalisation — restricted pre-admission foundation

**Purpose:** Deal with a meaningful portion of non-canonical and mixed-content PDFs without weakening Verivaro's strict evidence-ingestion allowlist. This is a separate **offline operator/worker-side converter**, not an HTTP endpoint and not an enabled browser feature. It never sends untrusted PDF bytes to the application database or OCR image worker. Conventional PDF is decoded by Poppler in a separately restricted environment; only the derived canonical single/2–4-page RGB image PDF is eligible to pass the existing format validator.

**Bounds:** source <=256 KiB, PDF header required, pdfinfo reports 1–4 pages, explicitly unencrypted and JavaScript-free; each page independently rendered using fixed PPM arguments with maximum dimension 720 px, capped subprocess output/timeout and no shell, no inherited application environment, one converter process call at a time, and total <=2,097,152 pixels. Output is rebuilt in the known byte-exact canonical PDF structure and verified independently using Verivaro's parser. Rejects unsupported output (e.g. large incompressible scans), malformed PPM, output overruns and access cancellation.

**Critical provenance distinction:** A normalized PDF is a **derived copy**. The manifest separately binds the original hash and length and the derived hash and page raster digests but does **not** retain the original PDF or cryptographically prove the converter rendered it faithfully. PDF text, layers, interactive forms, annotations, attachments, and metadata may disappear. It must never be represented as the customer's authenticated original; the original should be handled in a separate evidentiary custody workflow if that is needed. Independent human review is still mandatory for OCR. PDFinfo preflight is not a security sandbox and Poppler can be vulnerable; **production requires separately enforced Linux namespaces/seccomp, non-root identity, network isolation, cgroup resource limits and controlled staging**, independently tested before exposing any upload or connecting this converter to the app.

**Verification:** deterministic fakes test active-content/encryption rejects, page limits, malformed raster, abortion, source/derivative SHA, and canonical output; actual Poppler renderer runs in CI against independently produced two-page text PDF. No real documents, cloud OCR, production deployment or paid infrastructure used.

**Still outstanding:** secure authenticated quarantine ingress, sandbox enforcement on production Linux, document loss review, page fidelity benchmarks, automatic provenance chain of custody linking original and derivative, full-size/scanned photo handling and customer testing. There is no claim of support for *all* PDF variants.
