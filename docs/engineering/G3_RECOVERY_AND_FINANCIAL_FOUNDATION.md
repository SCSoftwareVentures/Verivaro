# Recovery review and financial intelligence foundation

Recovery proposals pin an elapsed, approved historical schedule revision, the current criterion version, exact existing scoped source digest and a bounded rationale. A reviewer distinct from author, proposer and source uploader can approve the approach for assessment or reject it. Immutable records and retry responses preserve the original deadline. A late/source photo cannot automatically satisfy an inspection; approval grants neither an evidence pass nor an exception waiver. This intentionally leaves the existing release policy untouched. A separate formally authorised waiver policy and any permitted release exceptions still require explicit authority, supporting source review and independent controls. No legal or statutory conclusions.

The standalone PaymentReady / MoneyMap / RetentionWatch kernel uses exact canonical decimal-to-minor-unit BigInt arithmetic, a restricted explicit currency list, stable current-version documentary condition checks, independently approved source-backed records, deduplicated record IDs and distinct currencies, tax bases and amount categories. Unknown amounts and dates are explicit; pending, rejected and integrity-invalid records never contribute to confirmed totals. It distinguishes documentary blockers from entitlement and separates retention, dispute and milestone sums. Financial persistence, amendment and reviewer workflow, integrations, UI and dedicated browser tests remain outstanding. Unit and HTTPS acceptance tests added alongside migration and backup hash reconciliation. No production deployment, external notifications or automatic payment. Verification is deferred to the grouped checkpoint.
