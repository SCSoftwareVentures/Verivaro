# G1 session identity revocation

Migration 0005 requires a registered active UUID session associated with the authenticated actor. The trusted authentication service must register the session before token issuance; JWTs now require a signed sid claim. Version 2 HMAC contexts bind actor, tenant, backend, full transaction ID, expiry and session. Old v1 contexts and tokens without sid fail closed. Deploy migration and signer together (planned outage until both are upgraded).

The database checks session status and expiry in every statement snapshot; revoked sessions cannot be restored, reassigned or deleted by ordinary DML. Recovery uses a fresh session identifier after approved reauthentication. Other active sessions remain valid unless actor-level disable applies. No public registration, recovery or revocation endpoint exists yet. The trusted issuer, IdP event ingestion, MFA recovery, scoped administration and retention policy still need implementation. No production session or customer data has been used. Existing long-running statements may complete before revocation is observed; active cancellation is a separate control. This gate does not certify full OIDC integration or share-link revocation.
