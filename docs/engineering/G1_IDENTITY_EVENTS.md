# Identity lifecycle and signing-key rotation

Signed Ed25519 keyset catalogues bind the exact issuer/audience, RSA verification keys and explicit monotonic sequence, issued/expiry times and separately trusted SHA-256 checkpoint. Rotation is atomic in one process, removes retired keys immediately, and fails closed when the keyset expires. Persist the newest trusted checkpoint independently before restarting any replica; distributing consistent catalogues/checkpoints and keyset approval is an operator responsibility. This is controlled rotation, not automatic remote JWKS discovery. No JWT-supplied key URLs. External IdP key acquisition and provider-native rotation are not verified.

A separately credentialed event receiver accepts canonical seven-field, Ed25519-signed lifecycle events from an approved integration adapter. It is not a standard OIDC back-channel logout or SCIM implementation. Only logout and permanent disable are supported; no event can enroll, enable or rebind. Issuer, audience, event UUID and freshness are bound to the signature. Database replay deduplication is bounded to 10000 recent events and 15 minutes; messages are accepted for at most four minutes by receiver and five minutes by DB. Unknown subjects are acknowledged without mutation. Old events cannot be replayed to revoke a fresh session within that window. Actual sender authentication, TLS transport, delivery guarantees, clock synchronization, incident investigation and provider-specific event mapping remain deployment obligations. On saturation the receiver fails closed; monitor and retry legitimate events. Disable is irreversible through this interface. Distinct event service role cannot register sessions.

Global logout is same-origin POST /auth/logout-all and requires a current browser session. All actor sessions are revoked in the serialized identity transition, and a fence rejects earlier authentication proofs; stale browser handles become unusable without immediately deleting all their rows. Provider logout has the same effect. Authentication callbacks record bounded aggregate outcomes (best effort, no raw tokens, IP or identity data), with warning after 20 denials over five minute buckets and existing escalation/outbox support. The signal is not proof of attack; tune thresholds in production. Callback metrics do not cover all possible external errors or edge attempts. Recovery clears volatile browser login state and authentication telemetry, retaining recent lifecycle replay records. CI uses synthetic keys/events and live PostgreSQL only; no production provider connected.
