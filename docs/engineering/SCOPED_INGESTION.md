# G1 scoped ingestion and identity boundary — draft

CI #2 and #3 passed both jobs on foundation SHA 2556a5ec44a3c5f8de894143d9e871b947c66da6. This increment adds a pure RS256 access-token verifier with trusted, preconfigured issuer, audience and keys (no remote discovery), a dedicated NOLOGIN signer role and database procedures for actor-bound document metadata and pending upload intentions. The issuer/subject passed to the signer must originate only from verified access tokens. Use a distinct credential/pool for signer and runtime; never permit runtime to SET ROLE signer. Gateway must bind context to the actual runtime transaction and use READ COMMITTED. No application login flow or HTTP API wired yet. Do not expose signer directly to clients.

OIDC provider must issue dedicated API access tokens, not ID tokens; provider-specific token-type/audience enforcement and JWKS cache/rotation remain integration requirements. JWT verifier currently allows JWT/at+jwt/absent typ for compatible issuers; restrict provider configuration accordingly. No immediate IdP revocation, session tracking or remote JWKS client. Signing key rotation and true distinct-login concurrency tests remain outstanding.

Upload intentions contain claimed hash, type and size only; never become actual document versions, parsed files, clean status, evidence or share grants. Blob upload credentials, streaming verification, quarantine scanner, audit events, rate limits, expiry/cleanup, retention and HTTP idempotency keys are outstanding. Pending intents deduplicate on scoped UUID and exact payload and actor; no raw runtime reads or writes added. Audit event infrastructure and immutable lifecycle transitions remain required before real data. The write procedures lock membership rows to serialise with revocation; independent concurrency and pooled connection integration tests still needed.

All data and keys in CI are synthetic or generated for the test. No deployment, production authentication or full G1 acceptance.
