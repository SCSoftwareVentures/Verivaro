# Performance and incremental intelligence
Baseline CI #79 passed all ten jobs. This increment replaces repeated Unicode prefix allocations with a sparse offset index per referenced source. Every requested span is still validated and final readiness is evaluated in full. Complexity shifts from repeated O(source length) work per link to one bounded traversal per referenced source plus requested-offset sorting.

The service uses a process-private bounded LRU/TTL intelligence cache scoped by tenant, project, upload, engine version, ordered page identities and provider mode. Actual page hashes and extraction method are validated before lookup. Page-level deterministic candidates reuse unchanged pages; exact full requests reuse validated advisory output, simultaneous identical provider work coalesces, and failure results are not cached. Cached objects are serialized and cloned; no authority, readiness or persistent original data is cached. Every API request still authorizes the database read and reauthorizes before returning, comparing a length/structure-safe ordered fingerprint rather than concatenation-only text digest. Cache is limited to 128 entries, 4 MiB serialized key/value budget and 60 seconds since insertion (expired values removed on access; not secure memory wiping). Provider capacity limits remain.

Benchmark logs compare a repeated-prefix reference evaluator against sparse evaluation on 500 links, and measure cold/repeat/one-page-changed analysis with exact equivalence assertions and nine unchanged-page hits. Timing is diagnostic, not a hard speedup target; no real OCR/network/DB end-to-end SLA or distributed cache claim. CI pending. Production multi-process policy, stronger memory lifecycle guarantees, independent benchmark validation and live AI remain outstanding. No external model or additional expense.
