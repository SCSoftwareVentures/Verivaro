# Bounded encrypted large export delivery

Optional spoolDirectory enables disk staging instead of whole-file RAM buffering. Existing 8 MiB default remains; explicit settings allow up to 512 MiB per export and a 2 GiB aggregate configured staging budget (plus GCM tags and filesystem overhead). Each artifact is streamed into independent 256 KiB AES-256-GCM blocks with ephemeral 256-bit key, unique indexed nonces and index/length authenticated data. The ciphertext file is opened exclusively with mode 0600 and unlinked immediately; a successful request creates no persistent named artifact. The full SHA-256 digest is compared with the approved export before any HTTP bytes are sent. Authorization is checked again before delivery. The encrypted blocks are decrypted and individually authenticated before transmission; backpressure is respected. Cleanup closes the descriptor and clears the key on normal exit and error.

CI contains actual 64 MiB HTTP delivery, hash/length verification, anonymous-file cleanup, fragmentation and failure tests. The recorded timing is synthetic single-request local throughput, not production capacity or a guaranteed speed. The 512 MiB cap is a configured limit pending maximum-size load testing. A partial response can occur after sending headers if a later encrypted block fails authentication or the connection times out; unauthenticated block bytes are never emitted. Spool parent and its ancestors must be trusted, isolated and have a dedicated quota; configure process and storage limits. Encryption protects staging at rest, not the separate original storage or network; TLS and private source encryption are deployment requirements. Deadline remains cooperative for drivers; high-latency large downloads may need a revised timeout policy. No cloud deployment, paid storage or external delivery.
