# Encrypted PostgreSQL logical backup and isolated restore

Candidate recovery tooling uses pg_dump custom archive and pg_restore single transaction. Archive AES-256-GCM, random salt and nonce, separate HKDF-derived manifest HMAC key; manifest binds installation, source database, backup UUID, time, ciphertext hash, plaintext hash, size and tag. Files are 0600 in private 0700 directories, fsynced and atomically published after successful dump; max compressed archive 512 MiB. Restore authenticates and checks full archive before creating target, with decrypted bytes staged in anonymous encrypted temporary storage. Never prints database contents or encryption key. Key must be provisioned/stored separately, securely escrowed and rotated by deployment owner. Source and recovery settings are explicit.

Run node services/database-recovery/main.mjs backup /absolute/private/backup-root with explicit PGHOST, PGUSER, PGDATABASE, database credentials and VV_INSTALLATION_ID (UUID), VV_BACKUP_KEY (canonical random 32-byte base64url). Restore requires VV_RESTORE_APPROVED=1, private VV_RESTORE_SPOOL, same expected source database and installation, and target name verivaro_restore_*; creates a NEW target from template0, never replaces existing DB, revokes PUBLIC CONNECT and checks ordinary logins cannot connect. Restore as isolated migration owner; deploy on dedicated isolated recovery cluster/network, not a serving cluster. PostgreSQL roles and extensions must already be provisioned separately; source roles/config, WAL/PITR, object files, encryption keys, external provider state and notification receiver state are not included in logical dump.

Quarantine revokes all restored sessions and sharing links, disables known identities, rotates existing lockdown IDs and context key, deactivates recovery operators, prevents pending notification delivery, preserves resource leases and resets monitor heartbeat. This is a conservative incident recovery action, not a transparent failover. Do not grant application CONNECT or enable services until independently reconciled against post-backup revocations, current entitlements, evidence objects, outbox receiver state, and resource leases; rotate identity signing credentials and confirm trustworthy current identity mappings. Backup archive authentication does not prove freshness; replay protection requires trusted off-site backup catalog. Never automatically promote. If restore fails, target stays isolated and requires reviewed cleanup. RPO/RTO, multi-volume backup, real production disaster drill, off-site copies, retention, independent recovery operator review, role provisioning and object storage restore remain outstanding. CI uses synthetic database only. No production service is deployed.
