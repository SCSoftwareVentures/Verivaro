# Monitoring service and internal alert inbox

Install the pinned driver with npm ci --prefix services/security-monitor/driver --ignore-scripts --no-audit --no-fund. Provision separate NOLOGIN group memberships for dedicated nonprivileged worker and reader logins, and configure PGHOST, PGDATABASE, PGUSER and a protected password/credential source. Run node services/security-monitor/main.mjs worker for sequential sixty-second evaluations; run a separate process with reader credentials using node services/security-monitor/main.mjs reader. Reader binds only 127.0.0.1:8787 (configurable), with a dedicated random 32-byte canonical base64url VV_MONITOR_PASSWORD and HTTP Basic operator username. Supply via a protected secret mechanism, never command arguments or logs. Access remotely only via approved authenticated encrypted operator tunnel; never expose the listener directly or behind a public reverse proxy. Database TLS and certificate validation must be provisioned for remote database connections.

The read-only HTML dashboard shows the current heartbeat, capacity, open incidents and the latest 50 committed opened/escalated alerts with stable event IDs, automatically refreshes every 30 seconds and returns 503 on stale/unavailable heartbeat. No client scripts, no mutation controls, no raw account, operator login, token or file data. Database snapshot uses repeatable-read read-only transaction. Incident actions remain restricted SQL operator functions from migration 0012. The inbox is a durable internal notification view, not an external acknowledgement or delivery channel. Monitor worker retries sequentially and emits fixed status strings only; independent uptime check, service supervisor, production authentication integration, external notification routing and incident operator UI remain release work. No live production deployment.
