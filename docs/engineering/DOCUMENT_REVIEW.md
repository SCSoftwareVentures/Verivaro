# Document review increment
Native extraction uses fixed Poppler/Tesseract paths, temporary private files, bounded input (10 MiB), 20 PDF pages, 1 MiB extracted text, output/time caps. PDF page text first, OCR for blank pages and standalone PNG/JPEG. English only; OCR text requires human comparison with original. Real-binary CI fixtures, not production parser isolation. OS sandbox, CPU/memory/network limits, decompression/decoder limits, pinned OS image and tool versions, larger or encrypted documents, multi-language OCR and independent benchmarks remain open.
Parser may stage page drafts only under a valid extraction lease. Source digest, page number, extraction method and derived text digest are stored. Lexical must/shall/required/mandatory proposals and literal matches are bounded, non-exhaustive, unapproved. Project owner/reviewer may approve or reject a specific exact quote and literal criterion via scoped API; contributors and other tenants denied. Decisions are insert-only for runtime, idempotent and tied to exact page hash and Unicode code-point offsets. They are approved proposals, not canonical requirement or evidence revisions, and never assert readiness. No AI engine, precedence reconciliation, current-version pointers, reviewer original-file viewer, or final evidence graph integration yet. Existing exact UTF-8 extraction remains supported. New native adapter must be explicitly passed to processOneExtraction by a trusted worker; no production scheduling.
