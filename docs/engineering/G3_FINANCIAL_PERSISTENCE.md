# Financial persistence and workspace

Owner-only edits and independent reviewer decisions for milestone, retention and disputed-amount records. Read access restricted to matched owner/owner or reviewer/reviewer roles. A stable project/category/documented reference identifies each record; amendments create immutable revisions with independent decisions, not overwrites. Amounts are canonical strings independently checked in PostgreSQL and Node using exact minor units. A scoped evidence ID/digest and approved criterion versions are pinned and reviewed; source integrity or stale pins invalidate documentary readiness. Multiple blockers count the same record only once; unknown amounts never enter totals, and currency, tax basis and category remain separate. Reviewed history stays available; a pending amendment deliberately makes the previous amount historical rather than current. Recorded UTC dates are reminders only. No financial action, external alerts or statutory interpretation.

The responsive workspace supports source selection, current criterion checkboxes, creation, revision, review, grouped totals and history. Tests exercise role restrictions, exact arithmetic, duplicate references, immutable revisions and unknown amounts. Restore hashes and function grant allowlist updated. The user must assign the same documented reference to the same underlying item; the system does not infer semantic duplicates across different references. Dedicated browser acceptance, financial export and dispute/acknowledgment chronology are later increments. Full CI review at grouped checkpoint.
