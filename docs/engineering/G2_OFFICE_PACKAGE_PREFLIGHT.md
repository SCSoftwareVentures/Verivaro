# Office package preflight foundation

Corrected the full G1 service privilege audit to explicitly allow the existing scoped `import_source_line_v3` function only for `verivaro_runtime`; no grants or enforcement changes. Manual import's integration cases already ran before the audit rejected the missing allowlist entry in PostgreSQL #286.

Added a bounded, in-memory Office ZIP reader supporting stored and raw-DEFLATE XML parts with local/central metadata equality, exact offsets, CRC, expansion limits, single-disk structure, no extra fields/descriptors/encryption/ZIP64/comments/symlinks, no filesystem extraction, strict part names and case-insensitive duplicate refusal. Limits are 256 KiB archive, 256 KiB expanded part, 1 MiB total expanded, and 64 entries. A separate narrow DOCX/XLSX package preflight checks required/allowed parts and rejects selected unsafe XML constructs and external relationships. It does not validate arbitrary XML or Office semantics and is deliberately not connected to ingestion or evidence imports. Next increment: strict XML schema/relationship validation, deterministic paragraph/cell mapping, original encrypted storage and end-to-end provenance integration. No new dependency. Synthetic tests cover compressed/stored packages, emitted XLSX, traversal, aliases, bombs, metadata tamper and unsafe XML. CI pending.
